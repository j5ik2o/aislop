# aislop の規約（全ステップ共通）

aislop（AI が生成したコードの定型的なパターンを検出するスキャナ）の fork である j5ik2o/aislop で作業する際の規約。
正はリポジトリの文書（AGENTS.md、README、.aislop/ の設定）であり、本ファセットはその実行用要約である。矛盾したらリポジトリの文書が優先する。

## 緑の判定

- 緑の判定は検証の三点のみである。`pnpm typecheck` の型検査、`pnpm test` のビルドとテスト全件実行、`node dist/cli.js scan .` の自前スキャン（スコア 100、指摘 0 件）である。部分的な実行の成功を緑と言わない
- テストの全件実行は、並行実行の負荷で揺れることがある。全件実行でだけ失敗したテストは、単独で再実行した結果で切り分けてから判定する

## fork の規律

- このリポジトリは scanaislop/aislop の fork である。差分は Scala サポート自体に限る。組織向けのルールの追加、既定値やしきい値の変更、fork だけの機能は入れない
- プロジェクト側の調整は、使う側の `.aislop/config.yml`、rules.yml、baseline で行う
- takt の運用設定（`.takt/` 一式と `.gitignore` への `.mcp.json` の追加）は、オーナー指示による例外として main だけに入れる。feat/scala-support には入れない

## プルリクエスト

- 変更は main 宛てのプルリクエストで入れる。main のブランチ保護の必須チェックは `Check unresolved comments` である
- レビューボット（CodeRabbit、Bugbot など）のコメントは無視しない。読み、中身で判断し、直すか、理由を述べて反論する。未解決のスレッドが残るプルリクエストをマージ可能と言わない

## コミット

- コミットは加藤潤一の名前で作る。Co-Authored-By のトレイラーは付けない
- コミットされる文章に em-dash（U+2014）を使わない

## 作業範囲

- ゴールやタスクで指定された範囲の外は書かない。範囲外の変更が必要になったら、勝手に広げず、報告して止まる
