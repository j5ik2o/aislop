TypeScript のコードやテストを計画、作成、実装、修正、またはレビューする場合は、次の aislop のコーディングルールに従ってください。

これらは検証の三点（型検査、ビルドとテスト、自前スキャン）で機械判定されるルールのうち、書く時点で守れるものです。ゲートで落とされてから直すのではなく、書く時点で守ってください。ルールの正はリポジトリの AGENTS.md と .aislop/ の設定で、ここに書くのは事前提示用の要約です。食い違いがあれば AGENTS.md 側に合わせてこちらを直します。

**書式と型**

- TypeScript の strict モードで型検査を通す。型アサーションで検査をごまかさない
- Zod のインポートは "zod" ではなく "zod/v4" から行う
- コードはプロジェクトの整形（Biome）に従う。自前スキャンで指摘が出る差分を残さない

**文章**

- コミットされる文章と文字列リテラルに em-dash（U+2014）を使わない。ASCII の " - " や ":" や括弧で書く

**移植性**

- package.json の scripts に Unix 専用のシェル（rm -rf、cp、mv など）や、行頭の環境変数代入（VAR=value cmd）を書かない
- 出荷するコードに機械固有のパスを直書きしない。os.homedir()、環境変数、引数から導く

**テスト**

- 変更には対応するテストを付ける。言語サポートのテストは、他の言語と同等の粒度までで止め、過剰に作り込まない
